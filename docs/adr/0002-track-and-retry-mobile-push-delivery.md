# Track and retry mobile push delivery on the server

Mobile notifications currently use a direct send after saving the inbox notification, so a temporary delivery failure can leave the user with no device alert. We will track delivery attempts and retry transient failures on the server for all supported notification categories, respecting recipient preferences and targeting each signed-in device separately. This adds persistent delivery state and operational work, but allows recovery when the app is closed and prevents reliability from depending on the recipient's app running.

Provider acceptance and delivery receipts describe progress through the push providers; they do not prove that the operating system displayed an alert or that the recipient read it. Provider handoffs can rarely duplicate or drop an alert, so the system promises idempotent server attempts rather than exactly-once display. Device sign-out removes that device from future delivery eligibility, and retry expiration prevents stale alerts from being sent. Expo collapse and grouping identifiers support conversation/post summaries, while TTL/expiration bound queued delivery; Android force-stop still blocks alerts until the app is reopened.
